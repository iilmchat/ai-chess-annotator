## 1. `app/ingestion/eco.py`

`python-chess` **не содержит базы ECO** — только читает заголовок `[ECO]`,
если он есть в PGN. Поэтому модуль реализует две ступени:

1. `normalize_eco()` — заголовок `e21` / ` E21 ` → `E21`; мусор (`Z99`,
   `E2`, `""`) → `None`.
2. `lookup_eco()` — курируемая таблица префиксов SAN → код ECO,
   **самое длинное совпадение** (`OPENING_TABLE`, ~50 записей:
   Ruy Lopez, Italian, Scotch, Sicilian, French, Caro-Kann, Scandinavian,
   Alekhine, Pirc, Modern, Nimzo-Indian, KID, Grünfeld, QGD/QGA/Slav,
   Dutch, English, Réti, Larsen, Bird и др.).

`detect_eco()` = заголовок → таблица → `None`.

Почему таблица, а не «догадка по первому ходу»: `1.e4` → `B00` — это не
«дебют партии», а «королевская пешка, irregular». Подставлять такой код
везде — врать пользователю. Таблица даёт код только при совпадении
реального дебютного префикса; иначе `None` (KI-011).

Сознательно **не** включены в таблицу сомнительные строки: лучше меньше
покрытие, чем неверный код. Проверка «самое длинное совпадение» —
`test_eco_lookup_prefers_longest_prefix` (6 полуходов → `E20`, 7 → `E21`).

## 2. `app/ingestion/parser.py`

```python
parse_pgn(pgn_string) -> ParsedGame
parse_fen(fen_string) -> chess.Board
find_position_repeats(moves, *, initial_fen=None) -> list[PositionRepeat]
```

### 2.1. `parse_pgn`

1. Вход не строка / пустой → `InvalidPgnError`.
2. `chess.pgn.read_game(io.StringIO(...))`; `None` → `InvalidPgnError`.
3. `game.errors` непустой → `InvalidPgnError` со всеми ошибками в тексте.
4. Обход `game.mainline()`: для каждого узла — `san`, FEN **после** хода,
   `is_capture` (до push, чтобы работал en passant), `is_check` (после push).
5. Ноль ходов → `InvalidPgnError` («заголовки без movetext не анализируются»).
6. Эндшпиль: первый полуход, после которого `_is_endgame(board)`.
7. Фазы: `opening_end_ply = min(30, ply_count)`; если эндшпиль наступил
   раньше — граница дебюта сдвигается назад (`endgame_start_ply - 1`),
   чтобы фазы не пересекались (учебные окончания с FEN-стартом).
8. Метаданные: `?`, `??`, `????.??.??`, `""` → `None`.
9. ECO — `detect_eco(headers["ECO"], [san…])`.

### 2.2. Пороги эндшпиля

| Константа | Значение | Почему |
| :--- | :--- | :--- |
| `OPENING_MAX_PLY` | 30 | «до 15-го хода» из постановки (полуходы) |
| `ENDGAME_MATERIAL_THRESHOLD_CP` | 2000 | постановка: «суммарный материал < 2000» |
| `ENDGAME_MAX_PIECES` | 10 | постановка: «меньше 10 фигур» (считая королей) |
| `PIECE_VALUES` | 100/300/300/500/900 | классические ценности, К = 0 |

Условие: `материал < 2000 ИЛИ фигур < 10`. Для тестовой партии на
последнем ходу материал `4300`, фигур `19` → эндшпиля нет
(`endgame_start_ply = None`) — это факт, а не «заглушка».

### 2.3. `parse_fen`

`chess.Board(fen)` (синтаксис) + `board.is_valid()` (невозможная позиция:
нет короля, лишние фигуры, невозможный шах). `ValueError` оборачивается в
`InvalidFenError` с `from exc`. Пробелы/переводы строк по краям
срезаются.

### 2.4. `find_position_repeats`

Сравнивается «шахматная» часть FEN — первые 4 поля (фигуры, очередь хода,
права рокировки, en passant); счётчики хода и полухода игнорируются, иначе
один и тот же повтор не совпадёт. `initial_fen` позволяет поймать повтор
самой начальной расстановки (`first_ply = 0`). При тройном повторе обе
записи ссылаются на первое появление.

**Важно про название:** это повторы позиций внутри партии, а не
«транспозиции относительно теории» — для вторых нужна база дебютов
(KI-011 фиксирует границу).

## 4. Обоснование решений

1. **`io.StringIO` + `read_game`** — из постановки; читается первая партия
   (batch — T-017).
2. **`node.san()` вместо ручной реконструкции SAN** — SAN формирует сама
   библиотека, значит формат гарантированно совпадает с `push_san` в
   тестах.
3. **`is_capture` до `push`** — `board.is_capture(move)` учитывает en
   passant только из позиции *до* хода; после `push` пешка уже ушла с
   пятой горизонтали.
4. **Проверка «нет ходов» после обхода** — самая дешёвая защита от
   «заголовки без movetext» и от мусорного текста (оба случая дают
   `game` без ошибок).
5. **`_board_key` через `split()[:4]`** — не regex: FEN нормализован
   `python-chess`, лишних пробелов не бывает, но `split` не падает на
   странном вводе.
6. **Четыре поля, а не `board.transposition_key()`** — в python-chess есть
   внутренний `_transposition_key` (фигуры + очередь + рокировки +
   en passant), но он приватный; свои 4 поля проще проверить глазами.
