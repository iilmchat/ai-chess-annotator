## 5. Что не так

- **Атрибуция к конкретному полуходу не проверяется.** Текст «+3.0»
  сверяется со **всеми** оценками `MoveAnalysis` (before/after/PV). Если
  такая оценка была в другом моменте партии, ошибочная атрибуция пройдёт.
  Это остаток KI-023; шаг 1 закрывает только числовую достоверность.
- **Допуск ±0.5 — требование, а не точное совпадение.** «+0.50» при факте
  «+0.20» считается верным. Для грубых галлюцинаций (+3.0, +5.0) этого
  достаточно, но тонкие подмены (±0.4) не ловятся.
- **Только знаковые десятичные оценки.** «+5» без дробной части, «5.0» без
  знака и «мат в три» не извлекаются — это может быть номер хода/варианта,
  и ложные срабатывания дороже пропуска. Паттерн намеренно узкий, как в
  постановке (`[+-]\d+\.\d+`, «мат в \d+»).
- **Перспектива не определяется.** Оценки нормализуются к белым, как пакет
  фактов, но фраза «+0.2 за чёрных» будет сверена с +0.2 за белых и
  пройдёт. Явного разбора «за кого» нет.
- **Без `analyses` проверка чисел выключена.** Это обратная совместимость
  для одиночных вызовов; `generate_commentary` всегда передаёт анализы, но
  внешний код может забыть — тогда числа не проверяются.
- **Сегментация всё ещё эвристическая.** Десятичные дроби больше не
  разрезаются, но сокращения/инициалы (`т. е.`, `Gukesh, D.`) могут дать
  неверные границы; это ограничение общего токенизатора, а не оценок.
- **Метрика «доля верных атрибуций» на 30–50 партиях не снята** — для неё
  нужен живой прогон/судья. KI-023 остаётся Open.
- **Regex может поймать `[%eval -1.50]`**, если модель процитирует PGN-тег.
  Это всё равно числовое утверждение, поэтому считается ошибкой только при
  расхождении с фактами.

## 7. Обоснование

- **Почему отдельный `EvaluationClaim`, а не расширение `SemanticClaim`.**
  У оценки нет поля/фигуры, зато есть число/мат; общий класс с
  `square: int | None` сделал бы `_claim_holds` и все вызовы ветвистыми.
  Раздельные типы сохраняют инварианты существующих утверждений.
- **Почему сверка со всеми `MoveAnalysis`, а не с «ключевыми моментами».**
  Пакет фактов содержит оценки before/after/PV; модель может законно
  цитировать любую из них. Сравнение с полным набором снижает ложные
  срабатывания, пока нет привязки к полуходу (остаток KI-023).
- **Почему нормализация к белым.** Пакет фактов печатает «оценка за белых»;
  `MoveAnalysis` хранит оценку с точки зрения сделавшего ход. Без
  `sign = +1/-1` по чётности ply текст «-0.20» для чёрного хода ложно
  отклонялся бы.
- **Почему ±0.5 пешки.** Требование шага; это половина пешки, достаточная
  для грубых ошибок и не наказывающая округление «+0.20 → +0.5». Допуск
  вынесен в `EVAL_TOLERANCE_PAWNS`.
- **Почему проверка только при переданных `analyses`.** `validate_semantic_claims`
  — публичная функция; старые вызовы без анализа не должны внезапно
  отклонять текст. Сервис передаёт анализы всегда.
- **Почему decimal-aware `_SENTENCE_TOKEN`.** Без этого `strip_invalid_claims`
  не мог удалить предложение с `+3.0`: он искал `+3.0` в обрывках
  `+3.`/`0`. Исправление минимальное и не меняет границы обычных фраз.
- **Почему обобщён `semantic_warning`.** Подсказка больше не говорит только
  о фигурах: теперь она про «утверждения, не согласующиеся с фактами», что
  покрывает и оценки. Существующие тесты проверяют только ключевые слова
  (`ВНИМАНИЕ`, `Перепиши`), поэтому контракт не сломан.
- **Почему тесты разделены unit/integration.** Unit проверяет чистую
  математику допуска и извлечения без БД; integration — что сервис
  действительно передаёт `analyses` и что retry/strip работают на
  `generate_commentary`.
