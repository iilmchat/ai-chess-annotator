## 1. Что умеет приложение

- принимает PGN (включая партии с FEN-стартом через `[SetUp]`/`[FEN]`);
- разбирает партию Stockfish: оценки, лучший ход, потеря в сантипешках,
  классификация (`blunder`/`mistake`/`inaccuracy`/…), мотивы;
- показывает доску, список ходов, оценку и рекомендацию под выбранный
  уровень;
- генерирует комментарий через LLM и **проверяет все SAN-ходы** валидатором;
- позволяет отредактировать комментарий и сохранить правку в датасет
  (`edits`);
- отвечает на вопросы по партии с тем же контекстом и валидацией.

Поддерживаются три уровня: **новичок**, **клубный игрок**,
**гроссмейстер**. Чем они отличаются — в
[ASSISTANT_LEVELS.md](ASSISTANT_LEVELS.md).

## 2. Запуск

### 2.1. Production-подобный стек (рекомендуется для проверки MVP)

```bash
cp .env.example .env          # заполнить ключи, если нужен gm/облако
docker compose -p chessannotator-prod -f docker-compose.prod.yml up -d --build
```

Откройте `http://127.0.0.1:8000/` — это SPA, собранная Vite и раздаваемая
FastAPI. API и healthcheck — там же:

```bash
curl -s http://127.0.0.1:8000/v1/health
```

> На dev-машине порт 8000 может быть занят другим контейнером (KI-002).
> Тогда задайте `API_PORT=8010`, `PROD_POSTGRES_PORT=5435`,
> `PROD_REDIS_PORT=6382`:
> `API_PORT=8010 docker compose -p chessannotator-prod -f docker-compose.prod.yml up -d --build`.

### 2.2. Разработка (два процесса)

```bash
# терминал 1 — API
uvicorn app.main:app --host 127.0.0.1 --port 8010

# терминал 2 — Vite с прокси на API
VITE_API_PROXY=http://127.0.0.1:8010 pnpm --dir web dev
```

Откройте `http://127.0.0.1:5173/`. Vite проксирует `/v1` на API.

Для локальной LLM нужен LM Studio с OpenAI-совместимым сервером на
`http://127.0.0.1:8034/v1` (модель `qwen/qwen3-4b-2507`). Для уровня `gm` —
`DEEPSEEK_API_KEY`. Без LLM анализ и доска работают, а генерация вернёт
`503`.

## 3. Сценарий: от PGN до комментария

1. Откройте приложение. В левой колонке уже вставлена демо-партия
   (Svidler — Shirov) — можно заменить её своей.
2. Вставьте PGN в поле **«Партия»**. Поддерживаются многоходовые партии и
   комментарии PGN; ходы должны быть легальны.
3. Выберите **«Уровень объяснения»**: новичок / клуб / гроссмейстер.
4. Нажмите **«Разобрать партию»**. Подождите: анализ 40 ходов на «клубе» —
   около 10–15 секунд, на «гроссмейстере» — дольше.
5. Появится доска с последней позицией, список ходов, сводка ошибок и
   карточка выбранного хода. Кликайте по ходам, чтобы листать партию.
6. Нажмите **«Сгенерировать»** в панели **«Комментарий»**. Текст
   появляется сразу, по мере генерации (SSE + «печатная машинка»); рядом
   есть **«Остановить»**. Для `gm` используется DeepSeek.
7. Прочитайте текст. Если нужно — нажмите **«Редактировать»**, поправьте и
   сохраните (**«Сохранить правку»**). Появится `edit #N` — запись ушла в
   датасет.
8. Нажмите **«Скачать PDF»** рядом с «Редактировать» — сервер соберёт PDF
   с шапкой партии (игроки, турнир, дата, результат), ходами, текстом
   комментария и **диаграммами доски**: финальная позиция + до двух
   критических моментов (если в окружении доступен рендерер cairo; иначе
   PDF будет без картинок, но скачается). Файл `commentary-{id}.pdf`
   скачается в браузере.
9. Задайте вопрос в панели **«Чат по партии»** (например, «Кто играл
   белыми?» или «Почему 12.Bb3 был ошибкой?»). Ответ тоже стримится.
10. Переключайте язык интерфейса кнопками **RU/EN** в правом верхнем углу.

## 4. Разбор интерфейса

### 4.1. Левая колонка

| Элемент | Назначение |
| :--- | :--- |
| Поле **«Партия»** | PGN; кнопка **«Пример»** возвращает демо-партию |
| **«Уровень объяснения»** | влияет на глубину анализа, рекомендацию и LLM |
| **«Разобрать партию»** | `POST /v1/analyze`, сохраняет анализ в БД |
| **«Сводка»** | игроки, ECO, число зевков/ошибок/неточностей, время анализа |
| **«Ходы»** | список полуходов; цветовая метка класса, оценка, клик = переход |

### 4.2. Центральная колонка

- **Доска** — `react-chessboard` 5.12.1; позиция выбранного хода,
  последний ход подсвечен.
- **Карточка хода** — SAN, класс, оценка, лучший ход, потеря в cp,
  рекомендация Policy под уровень и мотивы.
- В начале партии показывается стартовая позиция.

### 4.3. Правая колонка

- **«Комментарий»** — модель, токены, число попыток, статус валидации,
  текст и кнопки генерации/правки/скачивания PDF.
- **«Чат по партии»** — история вопросов и ответов, подсказки, поле ввода.

## 5. Чат по партии

Чат отвечает **только по фактам сохранённого анализа**:

- метаданные партии (кто играл, событие, ECO);
- все ходы;
- ключевые моменты (класс, потеря, лучший ход, оценка);
- мотивы.

Подсказки в пустом чате:

- «Кто играл белыми и чёрными?»
- «Какой ход был главной ошибкой?»
- «Что было лучше в ключевой момент?»

Ответ LLM проходит через тот же SAN-валидатор, что и комментарий. Если
модель выдумала ход, стрим завершается событием `error` (код
`llm_invalid_output`), и текст не сохраняется. Чат **не хранит историю
между перезагрузками**: каждый вопрос — независимый запрос по
`analysis_id`.

## 6. Правка комментария

1. Сгенерируйте комментарий.
2. Нажмите **«Редактировать»**.
3. Измените текст (до 20 000 символов).
4. **«Сохранить правку»** → `PATCH /v1/commentaries/{id}`.

Что происходит:

- `commentaries.text` обновляется;
- `human_edited = true`;
- в `edits` добавляется строка `(original_text, edited_text, editor_id)` —
  датасет для будущего дообучения (T-104);
- интерфейс показывает `edit #N`.

Оригинал не теряется: каждая правка — отдельная запись, повторное
редактирование добавляет новую.

## 7. API без интерфейса

### 7.1. Анализ

```bash
curl -s -X POST http://127.0.0.1:8000/v1/analyze \
  -H 'Content-Type: application/json' \
  -d '{"pgn":"1. e4 e5 2. Nf3 Nc6 1/2-1/2","level":"club"}' | jq
```

Ответ содержит `analysis_id`, `initial_fen`, `analysis_level`, `moves[]`
(с `fen` после хода), оценки, мотивы и `recommended_move`.

### 7.2. Сохранённый анализ

```bash
curl -s http://127.0.0.1:8000/v1/games/25 | jq
```

Отдаёт ту же структуру, что `/v1/analyze`, плюс `analysis_level` и
`commentaries` — без повторного запуска Stockfish.

### 7.3. Комментарий

```bash
curl -s -X POST http://127.0.0.1:8000/v1/commentary \
  -H 'Content-Type: application/json' \
  -d '{"analysis_id":25,"level":"club"}' | jq
```

### 7.4. Стриминг (SSE)

```bash
curl -N -X POST http://127.0.0.1:8000/v1/commentary/stream \
  -H 'Content-Type: application/json' \
  -d '{"analysis_id":25,"level":"club"}'
# event: meta / event: delta / event: done | event: error
```

Аналогично `POST /v1/chat/stream` с `{"analysis_id","level","message"}`.

### 7.5. Правка

```bash
curl -s -X PATCH http://127.0.0.1:8000/v1/commentaries/11 \
  -H 'Content-Type: application/json' \
  -d '{"text":"Новый текст комментария"}' | jq
```

### 7.6. Чат

```bash
curl -s -X POST http://127.0.0.1:8000/v1/chat \
  -H 'Content-Type: application/json' \
  -d '{"analysis_id":25,"level":"club","message":"Кто играл белыми?"}' | jq
```

### 7.7. Ingest (админ)

```bash
curl -s -X POST http://127.0.0.1:8000/v1/ingest \
  -H "X-Admin-Token: $ADMIN_API_KEY" \
  -F 'file=@data/sample.pgn' -F 'source=my-collection' | jq
```

Без корректного `X-Admin-Token` — 401; если `ADMIN_API_KEY` не задан —
503.

### 7.8. PDF комментария

Endpoint защищён JWT: нужен access-токен владельца комментария (или
администратора).

```bash
curl -s -H "Authorization: Bearer $ACCESS_TOKEN" \
  http://127.0.0.1:8000/v1/commentaries/11/export/pdf \
  -o commentary-11.pdf
```

Ответ — `application/pdf` с `Content-Disposition: attachment`. PDF
содержит шапку партии, ходы, текст комментария и диаграммы доски
(финальная позиция + критические моменты; при отсутствии `cairosvg`/
`libcairo2` — без картинок, graceful degradation); чужая запись → 404.
Если в окружении нет TTF-шрифта с кириллицей — 503
`pdf_font_unavailable` (см. GETTING_STARTED §8.10).

### 7.9. Фоновая выгрузка датасета (админ)

В админке `/admin/exports/dataset` форма «Создать экспорт» запускает
фоновую джобу: сервер собирает JSONL, браузер не ждёт стрим. Статус
(`queued`/`running`/`done`/`failed`) показывается на странице, по
готовности появляется кнопка «Скачать JSONL».

API (admin; auditor — только чтение/скачивание):

```bash
# Создать джобу (фильтры как у streaming-экспорта)
curl -s -X POST http://127.0.0.1:8000/v1/admin/exports/jobs \
  -H "Authorization: Bearer $ADMIN_ACCESS_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"level":"club","schema_version":2}'

# Статус и список
curl -s -H "Authorization: Bearer $ADMIN_ACCESS_TOKEN" \
  http://127.0.0.1:8000/v1/admin/exports/jobs

# Скачать готовый файл
curl -s -H "Authorization: Bearer $ADMIN_ACCESS_TOKEN" \
  http://127.0.0.1:8000/v1/admin/exports/jobs/1/download \
  -o edits-1.jsonl
```

Файлы лежат в `EXPORT_DIR` (`data/exports/`) вне web-root; пока джоба не
готова — 409, если файл пропал/вне каталога — 410. Джоба не переживает
рестарт процесса (KI-053).

Полная схема — `GET /docs` (OpenAPI).

## 8. Ограничения и приватность

- **Ни один вариант LLM не показывается без проверки** легальности SAN.
  Семантическая сверка оценок с фактами — KI-023.
- **Уровни `beginner`/`club`** используют локальную LM Studio: партия не
  уходит в облако. `gm` по умолчанию использует DeepSeek — это осознанный
  выбор для качества; on-prem профиль — T-105.
- **Латентность:** локальная модель генерирует ~9 ток/с, но благодаря
  SSE текст виден сразу; полный ответ может идти до минуты.
- **RAG-эмбеддинги** — хеш-заглушка (KI-025); retrieval работает по
  позиции, семантика появится позже.
- **Правки** сохраняются в `edits`; персональные данные не собираются.
- **Rate limit** — 10 запросов/мин на IP для `/v1/analyze`,
  `/v1/commentary`, `/v1/chat`, `/v1/ingest` (KI-015).
- **Аутентификации в v0.1.0 нет** (KI-026): не выставляйте API в открытый
  интернет без reverse-proxy и ограничения доступа.

## 9. Troubleshooting

| Симптом | Причина / решение |
| :--- | :--- |
| `503 llm_not_configured` на `gm` | не задан `DEEPSEEK_API_KEY` |
| `503 llm_error` на `club` | LM Studio не запущена / модель не загружена; откройте LM Studio и проверьте `http://127.0.0.1:8034/v1/models` |
| `504 llm_timeout` | модель не успела за 120 с; повторите или сократите партию |
| `502 llm_invalid_output` | модель дважды выдумала ход; переформулируйте вопрос/повторите |
| `400 invalid_pgn` | PGN пустой, нелегальный ход или обрыв разбора (KI-012) |
| `429 rate_limited` | превышен лимит 10/мин; подождите `Retry-After` |
| Доска пустая | выбран ход без `fen` (старый API) — перезапустите анализ |
| Комментарий не появляется | проверьте `/v1/health`, LLM-провайдер и логи API |
