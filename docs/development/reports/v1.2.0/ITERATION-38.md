## 4. Smoke

**Чат (T-072).** В разборе выбрать ход (например, `1... e5`) → над чатом
появляется «Контекст: 1... e5» → ввести «Почему это плохо?» → в
промпте, который получает LLM, есть строка «Пользователь сейчас смотрит
на ход 1... e5 (1-й ход чёрных, оценка …). Если вопрос без явного
номера — «этот ход», «почему плохо», «а лучше?» — отвечай применительно
к нему.»; ответ относится к e5. Вернуться в начало партии → контекст
скрывается, `selected_ply` в теле запроса отсутствует (проверено
интеграционными и E2E тестами).

**Стрелки (T-073).** Мок-анализ с `recommended_move` на выбранном
полуходе → на доске сразу зелёная стрелка рекомендации. После
генерации комментария, где упомянуты ходы, появляются стрелки: зелёные
для хороших/рекомендованных, красная для хода, классифицированного как
`blunder`/`mistake`/`inaccuracy`; нелегальные в текущей позиции SAN
пропускаются; в режиме варианта (drag) стрелки скрыты.

**Промпты/eval.** В файлах промптов всех уровней есть правило 8 с
примером «потому что», в EN — `ALWAYS EXPLAIN WHY`; `scripts/evaluate_llm.py`
на тексте без объяснений даёт `has_explanation=False`, на «…потому что…»
— True, и печатает «Доля объяснений (потому что/так как/because): X% (N/M)»
в сводке и консольном итоге.

## 5. Что не так

| Ограничение | Детали / последствия |
| :--- | :--- |
| Промпты в БД dev-стенда устарели | `seed_prompts` вставляет только отсутствующие строки: в `chessannotator_iter37.prompts` остались старые версии промптов, поэтому живой eval на этом стенде будет использовать старый текст до пересида/правки через админку. Файлы-источники обновлены, тесты промптов читают `.txt` напрямую |
| `selected_ply = 0` | По ТЗ 0 — «стартовая позиция», и бэкенд отдаёт строку про старт; фронтенд 0 не отправляет (поле опускается), поэтому для веба поведение прежнее |
| Стрелки только для текущей позиции | SAN из комментария резолвится на отображаемой позиции: упоминания ходов других полуходов не рисуются (иначе нужна привязка хода к полуходу) |
| Стрелки обновляются не построчно | Текст комментария фиксируется после завершения SSE/правки, а не на каждом дельте — так доска не перерисовывается десятки раз |
| Стрелки скрыты в режиме варианта | Вариант пользователя — отдельный сценарий; показывать стрелки из комментария к основной линии было бы неверно |
| Красный цвет — эвристика | Только `blunder`/`mistake`/`inaccuracy`; `good`/`best`/`brilliant` и неизвестные классы — зелёные |
| Метрика объяснений эвристическая | Проверяются маркеры («потому что», «так как», «поэтому», «because», «since», …), а не качество объяснения; знаменатель — комментарии с непустым текстом |
| Real-backend E2E | Новые сценарии (`chat-context`, `board-arrows`) в mocked-режиме: чат требует живой LLM, стрелки — мок `recommended_move`/SSE (KI-040) |

## 7. Обоснование

- **Контекст — в user-промпт, а не в системный.** Системный промпт
  описывает роль и правила (он кэшируется/переиспользуется), а «на каком
  ходе смотрит пользователь» — часть конкретного запроса. Строка попадает
  в `prompt_hash` (через вопрос), поэтому семантический кэш не вернёт
  ответ, привязанный к другому полуходу; `None`/вне анализа сохраняют
  прежний хеш — обратная совместимость.
- **Тихий игнор устаревшего `selected_ply`.** Клиент может «убежать»
  вперёд (доска на полуходе, которого нет в сохранённом анализе) —
  падать из-за этого чат не должен; контекст просто опускается.
- **Стрелки — на клиенте, без нового API.** SAN уже извлекается из
  текста; `chess.js` есть в бандле; проверка легальности на текущей
  позиции отсекает упоминания из других моментов партии. Бэкенд не
  меняется (эндпоинт `suggested_moves` из ТЗ был опциональным) — меньше
  контрактов и кэшей.
- **`commentaryText` в `analysisStore`.** Текст комментария рождается в
  `CommentaryPanel` (соседняя колонка), а стрелкам нужен в
  `AnalysisWorkspace`; общий store — минимальная связка без prop-drilling,
  не персистится (текст зависит от анализа и не должен переживать
  перезагрузку).
- **Рекомендация — базовая стрелка, комментарий — дополнительные.**
  Рекомендация уже есть в анализе (`recommended_move`), поэтому работает
  сразу, ещё до генерации; упомянутые в тексте ходы добавляются, когда
  текст появился. Так доска полезна и без комментария.
- **Правило «объясняй причины» в промптах + метрика.** Требование
  «объясняй, а не констатируй» нельзя проверить SAN-валидатором — это
  стилевое свойство, поэтому оно закреплено в промпте (жёсткое правило +
  пример), а в eval добавлена дешёвая проверка маркеров, дающая
  измеримый тренд качества без LLM-as-judge.
- **Версия 1.2.0.** Новые пользовательские возможности (контекст чата,
  стрелки) + изменение промптов/eval — минорный релиз по SemVer.
