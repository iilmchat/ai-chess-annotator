# Итерация 37 — Interactive Board & Semantic Validation (T-070, KI-023)

**Дата:** 2026-10-30
**Статус:** ✅ завершена. Версия — **1.1.0**.
**Формат:** RULES §2.18 (7 разделов).

Две главные претензии пользователей после релиза: (1) нельзя двигать
фигуры и смотреть варианты прямо в разборе, (2) LLM «галлюцинирует»
факты о позиции — пишет «слон на e6», когда слона там нет, или «связку
пешки f7», которой не существует. Плюс бытовое: PGN удобно загружать
файлом, а не вставлять текстом. Все три пункта закрыты.

## 4. Smoke

**Backend (семантика).** Через integration-тест со scripted LLM:

1. Модель отвечает «Слон на e6 контролирует центр.» на партию, где слона на
   e6 нет → `validate_semantic_claims` возвращает `(["слон на e6"])`,
   сервис переспрашивает (в промпте второй попытки — пакет фактов +
   «ВНИМАНИЕ: … утверждения о фигурах, которых нет на доске: слон на e6 …
   Перепиши комментарий»), вторая попытка чистая → `attempts=2`.
2. Последняя попытка (`max_retries=0`) с галлюцинацией → ответ 200 с
   текстом без offending-предложения («Партия началась с хода d4.»), в логе
   `commentary_semantic_stripped` (problems=1, stripped=true).
3. `semantic_validation_enabled=False` → текст возвращается без фильтра.
4. Нелегальный ход по-прежнему даёт retry и затем 502 — поведение итерации
   35 не изменилось.

**Frontend (доска и загрузка).**

1. `/` → кнопка «Загрузить файл» (📎) → выбрать `game.pgn` (0.4 КБ) →
   текст появляется в поле, «Разобрать партию» → `/analysis/:id`.
2. Выбрать файл 1 МБ + 1 байт → баннер «Файл больше 1 МБ — выберите другой
   PGN.», поле не изменилось; `.txt` → «Нужен файл с расширением .pgn.».
3. В разборе перетащить коня f3 → g5: появляется строка
   «Вариант: 3. Ng5», фигура реально на g5, подсказка исчезла.
4. Второй ход c6 → d4: «Вариант: 3. Ng5 Nd4».
5. «Сбросить на партию» — строка исчезает, доска возвращается к позиции из
   базы; повторный вариант + кнопка «назад» (навигация) — вариант тоже
   сбрасывается.
6. Нелегальное перетаскивание (ладья a1 → a5 через свою пешку) — ход не
   принимается, вариант не создаётся.
7. Существующие фичи (шкала, график, навигация, PDF/PGN-экспорт,
   комментарий, чат) — без регрессий (общий E2E 42/42).

## 5. Что не так

| Ограничение | Детали / последствия |
| :--- | :--- |
| Семантика проверяет не всё | Проверяется **существование** фигуры на поле (и цвет/тип, если названы), но не геометрия связки, не оценки, не мотивы, не атрибуция «лучшего хода» и вариантов к полуходам — это отдельный NLI/rule-слой. KI-023 остаётся **Open** (частично закрыт) |
| Утверждение валидно, если верно хотя бы в одной позиции партии | Привязка утверждения к конкретному полуходу требует разметки предложений по ходам; выбор «любая позиция» сделан против массовых ложных срабатываний. Обратная сторона: «слон был на e6» в неверный момент не отловится |
| Извлечение эвристическое | Нужен предлог «на/on» (фраза «слон e6» не считается утверждением); один pin-claim на поле+предложение; наивная сегментация предложений по `.!?…` может странно резать сокращения и числа вида «+120.5» при вырезании |
| Fallback при полном отбрасывании | Если все предложения невалидны, `strip_invalid_claims` возвращает исходный текст (никогда не пустой) — деградация вместо пустого комментария |
| Загрузка PGN: только расширение | MIME-снифинг содержимого не делался (по ТЗ); файл с расширением `.pgn`, но не-PGN содержимым дойдёт до анализа и вернёт ошибку парсинга |
| Варианты не сохраняются | Локальное состояние, сбрасывается при навигации/смене анализа; экспорт варианта не требовался |
| `app/main.py` | В рабочем дереве был незакоммиченный WIP (Windows Proactor policy) с нарушенным порядком импортов; исправлен порядок, поведение сохранено — правка включена в коммит как `fix` |
| Real-backend E2E | Новые сценарии проверены в mocked-режиме (KI-040) |

## 7. Обоснование

- **Почему семантический слой отдельным модулем.** SAN-валидатор
  (`app/engine/validator.py`) остаётся чистым и не менялся; семантика —
  независимый слой с собственным API (`extract`/`validate`/`strip`), его
  можно включать флагом и тестировать без LLM и HTTP. Интеграция — в
  существующем retry-цикле `_generate_with_validation`, поэтому новое
  поведение не дублирует логику попыток.
- **Почему «валидно хотя бы в одной позиции».** Требовать совпадения во
  всех позициях нельзя: комментарий описывает конкретный момент, и такая
  проверка отбраковывала бы корректные фразы (массовые 502/пустые тексты).
  Мы закрываем именно жалобу «фигуры там нет» — ложные утверждения,
  неверные нигде.
- **Почему на последней попытке вырезаем, а не падаем.** Пользователь
  должен получить комментарий: 502 из-за одного предложения хуже, чем
  текст без ошибочной фразы. Вырезание — с сохранением абзацев и
  гарантией непустого результата; логируется счётчиками (без текста LLM и
  PII).
- **Почему `python-chess` для проверки.** Уже зависимость и единственный
  источник правды о позиции: утверждение проверяется `board.piece_at`,
  позиции строятся тем же способом, что в SAN-валидаторе (старт + mainline
  + PV), — согласованность двух слоёв.
- **Почему интерактивность в `Board.tsx`, а состояние — в workspace.**
  Доска осталась презентационной (props + колбэк), поэтому вне разбора
  (`HomePage` без анализа) она по-прежнему «просмотровая», а вся логика
  варианта (какой ход, какая строка, когда сбросить) живёт рядом с
  `selectedPly` в `AnalysisWorkspace`; чистые хелперы в `lib/variant.ts`
  тестируются в node без DOM и переиспользуются E2E.
- **Почему drag проверяется настоящей мышью.** react-chessboard 5
  использует dnd-kit с pointer events; E2E двигает курсор
  (`move`→`down`→`move` с `steps`→`up`) по координатам `[data-square]` —
  это доказывает, что доска реально интерактивна, а не что «компонент
  отрисован». Нелегальный дроп проверяется отдельным кейсом (фигура не
  уезжает).
- **Почему загрузка PGN — через отдельный lib.** Валидация размера/типа и
  чтение файла вынесены в `lib/pgnFile.ts` с инъекцией `FileReader`:
  границы (1 МБ, `.pgn`) покрыты unit-тестами в node, а реальный
  `FileReader`/`setInputFiles` — E2E. `HomePage` только связывает это с
  существующим баннером ошибок.
- **Почему версия 1.1.0.** Итерация добавляет пользовательские фичи
  (интерактив, загрузка файла) и новое поведение валидатора — минорный
  релиз по SemVer; отчёт и CHANGELOG ведутся в `v1.1.0`.
