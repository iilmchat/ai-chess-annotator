## 1. Миграция не понадобилась

Постановка просила «добавить поле `multipv` (JSONB) в `moves` и создать
миграцию». Проверка фактической схемы:

```
moves.multipv | jsonb | nullable
```

Колонка создана ещё в **T-004** (первая миграция `b802598c3778`), там же
есть таблица `motifs(move_id, type, description, importance)`. Поэтому:

* новая миграция **не создавалась** — она была бы `ALTER TABLE ... ADD
  COLUMN multipv`, который упал бы с «column already exists»;
* `alembic check` подтверждает отсутствие дрейфа (модели = миграции);
* KI-018 закрывается не изменением схемы, а **заполнением** колонки.

## 2. Что изменилось в коде

`MoveAnalysis` получил два поля:

| Поле | Что | Куда |
| :--- | :--- | :--- |
| `lines: list[EngineLine]` | MultiPV позиции **до** хода (альтернативы игрока) | `moves.multipv` (JSONB) |
| `motifs: list[Motif]` | мотивы позиции **после** хода | таблица `motifs` |

Заполняются в `build_move_analyses` — там уже есть и доски, и линии:

```python
lines_before = list(lines_by_position[index - 1])
motifs = detect_motifs(boards[index].fen(), list(lines_by_position[index]))
```

Почему линии «до», а мотивы «после»:

* `multipv` — это «что игрок мог выбрать»: ход оценивается относительно
  альтернатив, которые были **до** него;
* мотив — характеристика получившейся позиции («после хода возникла
  проходная пешка»), иначе описание противоречило бы картинке.

## 3. Запись в БД

`_persist` в `app/api/v1/analyze.py`:

1. `games` → `flush()` (нужен `games.id`);
2. список `(Move, MoveAnalysis)` → `add_all` → `flush()` (нужны `moves.id`);
3. `motifs`: `MotifRow(move_id=..., type=..., description=..., importance=...)`
   для каждого мотива каждого хода → `add_all`;
4. один `commit()` на всё.

Транзакция одна: либо сохранена партия со всеми ходами, мотивами и линиями,
либо ничего. Каскад `ON DELETE CASCADE` чистит `moves` и `motifs` при
удалении партии (проверено интеграционным тестом).

Дублирование имён `Motif` (модель мотива и ORM-таблица) разведено
импортом `from app.db.models import Motif as MotifRow`.

## 4. Размер данных

`multipv` — массив до 3 линий (уровень `club`), каждая с PV-вариантом.
Фактически: короткая партия из 6 ходов через API — 6 × 3 линии; полная
партия 53 хода — порядка 100 КБ JSONB. Это приемлемо, но при росте
глубины PV стоит укорачивать (кандидат в T-017, отмечено в KI-018).

## 5. Проверки

| Проверка | Результат |
| :--- | :--- |
| Короткая партия через API | 6 ходов, у каждого `multipv` с 3 линиями; мотивы 12 строк (`king_safety`) |

| Удаление партии | каскад уносит `moves` и `motifs` (тест не оставляет мусора) |
