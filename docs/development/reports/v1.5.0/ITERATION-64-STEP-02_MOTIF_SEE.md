## 5. Что не так

- **SEE одноходовый.** Учитываются только прямые атакующие/защитники и
  ценность; нет очереди взятий, рентгенов, связок и защит королём. Это
  лучше прежней эвристики, но не полноценный SEE Stockfish.
- **Король-атакующий отфильтрован.** Иначе король (ценность 0) делал бы
  «висящей» любую защищённую фигуру; король может взять только
  незащищённую, и этот случай покрыт веткой «нет защитников».
- **«Висящая» — только фигура соперника.** Мотив отражает возможность
  стороны, которая ходит (`hanging_piece` не сообщает о своих фигурах под
  боем). Это согласуется с `fork`/`pin`, но не является полным обзором
  слабостей.
- **Пешки не считаются мотивом.** `hanging_piece` требует ценность
  ≥ коня (`VALUABLE_TARGET=300`), иначе почти каждая позиция давала бы
  шум. Пешечные тактические удары остаются вне мотива.
- **Равный размен не «висит».** Защищённая фигура, атакованная равной по
  ценности, не попадает в `hanging_piece` и не делает вилку выигрышной,
  даже если тактически размен может быть полезен позиционно.
- **Вилка возвращает только первую.** Детектор по-прежнему отдаёт один
  `fork` на позицию (первый найденный), а не все.
- **Recall/precision KI-019 не измерены.** Размеченного набора 20 позиций
  нет; шаг 2 закрывает только «нет SEE». KI-019 остаётся Open (частично).
- **Новый тип мотива требует синхронизации потребителей.** Добавлены
  `MotifType`, API-тест и i18n, но внешние клиенты, которые
  перечисляют типы у себя, должны добавить `hanging_piece` сами.

## 7. Обоснование

- **Почему отдельная `is_piece_hanging`, а не порог в `_find_fork`.**
  Функция — самостоятельный примитив: её использует и новый мотив, и
  вилка. Тесты проверяют её на чистых позициях, не завязываясь на текст
  мотива.
- **Почему «самый дешёвый атакующий < ценность цели».** Это минимальная
  модель размена: если атакующий дешевле, даже ответный захват оставляет
  выигрыш. Равный размен не считается «висит» — иначе мотив срабатывал бы
  на каждом контакте равных фигур.
- **Почему король не атакующий.** У короля ценность 0, и формально он
  «дешевле» любой фигуры; без фильтра защищённая ладья становилась бы
  висящей. Ветка «нет защитников» отдельно покрывает законный захват
  королём.
- **Почему `hanging_piece` — новый тип, а не расширение `fork`.**
  Это разные факты: вилка требует ≥ 2 целей, висящая фигура — одной.
  Отдельный тип позволяет промптам/UI показывать их раздельно
  (`MotifType` — Literal, поэтому тип добавлен явно).
- **Почему только фигуры соперника.** Мотив — тактическая возможность
  стороны, которая ходит; так же устроены `fork` и `pin`. Свои фигуры под
  боем — отдельная тема (защита), её можно добавить позже.
- **Почему пешки исключены.** Иначе `hanging_piece` появлялся бы почти в
  каждой позиции и вытеснял более важные мотивы из `MAX_MOTIFS=6`.
- **Почему максимум два мотива.** Ограничение шума: две самые ценные
  висящие фигуры дают достаточно материала для комментария.
- **Почему обновлён i18n.** Новый тип приходит в API; без подписи UI
  показал бы сырой `hanging_piece`. RU/EN добавлены, frontend
  typecheck/test/build зелёные.
- **Почему KI-019 не закрыт.** Симптом включал recall ≥ 80% на размеченных
  20 позициях; SEE его не измеряет. Закрывать KI без метрики было бы
  подменой критерия.
