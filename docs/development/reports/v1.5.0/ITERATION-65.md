## 5. Что не так

- **5 партий — статистически мало.** Разница средних −1.00 выглядит
  значимой, но судья шумит; для решения «7B+чистые» нужен прогон на
  30–50 партиях (T-024).
- **3B vs 7B смешивает ёмкость и данные.** 7B обучена на шумных, 3B — на
  чистых; корреляция «7B+шумные > 3B+чистые» подтверждена, но
  изолированного сравнения «7B+чистые vs 3B+чистые» нет. Вывод о ёмкости
  опирается также на loss ≈ 0.5 (переобучение), а не только на eval.
- **v4 оценена только на `club`.** `gm`/`beginner` для 3B не прогонялись;
  выводы не распространяются на все уровни.
- **KI-030 закрыт при недостигнутом 7/10.** Это закрытие
  **исследовательского вопроса** (корреляция ёмкость/данные), а не
  достижение целевого качества; порог 7/10 остаётся ориентиром и
  зафиксирован в выводе.
- **Канонический JSON переключён на v4.** Старые ссылки на
  `llm_eval_results.json` теперь видят v4; baseline v3 сохранён
  отдельным файлом, но внешние потребители, читавшие канонический файл,
  должны учитывать смену модели.
- **Сырые v4-оценки взяты из `data/llm_eval_results_v4.json`** (локальный
  артефакт прогона) и скопированы в `docs/`; judge tokens/commentary_id
  сохранены как в исходнике. Повторный живой прогон в этой итерации не
  выполнялся — зафиксированы уже полученные результаты.
- **CHANGELOG фиксирует позитивный пайплайн, а не качество модели.**
  8 ГБ VRAM достаточно для обучения/экспорта 3B; для 7B нужен GPU
  12+ ГБ, это ожидание, а не проверенный факт в текущем окружении.

## 7. Обоснование

- **Почему same-sample.** v3 и v4 прогнаны на одном `eval_games.json`
  (5 партий, `club`, один судья/промпт) — только так дельты 0.00/−0.80/
  −2.20 сопоставимы (T-024/KI-023).
- **Почему `compare_evals.py`, а не ручная таблица.** Скрипт — единый
  источник дельт: он проверяет `(game_id, level)`, считает объяснения и
  CJK одинаково для обеих версий; таблица в `LLM_EVAL.md` буквально
  повторяет его вывод.
- **Почему канонический JSON — v4.** `evaluate_llm.py` по умолчанию
  перезаписывает `llm_eval_results.json` последним прогоном; отчёт v4 и
  канонический файл должны совпадать. Baseline v3 сохранён отдельно,
  чтобы сравнение оставалось воспроизводимым.
- **Почему KI-030 можно закрыть.** Симптом — «LLM-as-judge ниже 7/10,
  причина не установлена». Итерация 65 устанавливает причину:
  недостаточная ёмкость 3B; корреляция 7B+шумные > 3B+чистые; следующий
  шаг (7B+чистые) имеет критерий и инфраструктурное требование. Держать
  KI открытым как «модель всё ещё ниже 7/10» значило бы смешивать
  исследование с приёмкой следующей модели.
- **Почему вывод про 7B, а не «больше данных».** v4 обучена на чистых
  489 записях и всё равно 2.60; loss 0.5 и падение стиля/полезности
  указывают на переобучение/нехватку ёмкости. Data-centric без ёмкости
  не масштабируется — это и фиксирует README/LLM_EVAL.
- **Почему позитивный пайплайн в CHANGELOG.** Обучение и экспорт на
  AMD/8 ГБ VRAM — переиспользуемый инженерный результат, независимый от
  качества 3B; он снимает инфраструктурный блокер для 7B.
- **Почему README-таблица, а не только строка статуса.** Метрики v3/v4 —
  главный ответ на «какую модель катить»; таблица сразу показывает
  корреляцию и требование к GPU, не заставляя читать отчёт.
