## 1. Копия `PROMPT_FOR_DSH.md`

# Промпт для DSH: реализация проекта ChessAnnotator

## Твоя роль
Ты — ведущий full-stack-инженер и архитектор проекта **ChessAnnotator**.
Работаешь итеративно, по спринтам. Каждая итерация заканчивается
рабочим инкрементом, проходящим тесты и соответствующим Definition of Done
из `TODO.md`.

## Что мы строим
Веб-приложение с API, которое принимает шахматную партию (PGN/FEN) и
возвращает **комментарий гроссмейстерского качества**, адаптированный под
один из трёх уровней пользователя: **новичок**, **клубный игрок**,
**гроссмейстер**. Архитектура — гибридная: движок (Stockfish/LC0) и
база аннотированных партий дают проверенные факты, LLM превращает их в
связный текст, валидатор проверяет все варианты через движок.

## Обязательные входные документы (читай в этом порядке)
1. **`docs/development/SPEC.md`** — полная спецификация (архитектура,
   стек, БД, API, промпты, критерии приёмки). Источник истины.
2. **`README.md`** — общее описание, стек, быстрый старт, статус.
3. **`TODO.md`** — последовательный список задач с зависимостями и DoD.
   Работай по нему сверху вниз, не перескакивая через зависимости.
4. **`docs/README.md`** — навигация по остальной документации.
5. **`docs/development/RULES.md`** — правила кода, тестов и коммитов.

## Правила работы
- **Стек**: Python 3.12 + FastAPI (backend), React 19 + Vite (frontend),
  PostgreSQL 17 + pgvector, Redis + BullMQ-аналог (`arq`), Stockfish 17,
  vLLM для локальных LLM. Не меняй стек без явного согласования.
- **Итерации**: одна итерация = одна группа задач из `TODO.md`. В конце
  итерации — коммит, обновление `CHANGELOG.md`, отметка выполненных задач
  в `TODO.md` (`[x]`) и, при необходимости, обновление `KNOWN_ISSUES.md`.
- **Тесты обязательны**: каждая новая функция — с unit-тестом. Каждая
  итерация — зелёный CI (build, typecheck, tests, migrations).
- **Definition of Done** — см. соответствующую задачу в `TODO.md`.
- **Валидация LLM-вариантов**: ни один вариант из LLM-ответа не попадает
  пользователю без прогона через Stockfish (модуль `validator`).
- **Документация**: любое архитектурное решение — в `docs/development/`.
  Любая новая фича — в `USER_GUIDE.md` и `CHANGELOG.md`.
- **Безопасность**: JWT, rate limiting, секреты — через ENV + Vault/SOPS.
  Партии пользователей не уходят во внешние LLM без явного opt-in.

## Критерии готовности MVP (v0.1.0)
- Работает end-to-end: загрузка PGN → анализ → комментарий по трём уровням
  → веб-интерфейс с возможностью правки → чат по партии.
- 30–50 тестовых партий проходят с оценкой не ниже 7/10 (LLM-as-judge)
  и 100% валидацией вариантов.
- CI зелёный, Docker-образ собирается, `docker-compose.prod.yml`
  поднимает весь стек.
- README, USER_GUIDE, ARCHITECTURE, SPEC актуальны.

## Что делать прямо сейчас
1. Создай структуру репозитория и `docs/` по `README.md` и `TODO.md`.
2. Настрой `pyproject.toml`, `package.json` (frontend), `docker-compose.yml`,
   CI (GitHub Actions).
3. Создай скелеты документов из `docs/` с TODO-заглушками внутри.
4. Начни с задачи **T-001** из `TODO.md`.

## 2. Дополнения к копии (итерации 1–3)

Актуальные уточнения, которых нет в `PROMPT_FOR_DSH.md`:

1. **Отчёты по шагам** — `docs/development/reports/iteration-N/STEP-MM_*.md`,
   обязательные разделы: `RULES.md` §12.
2. **Отклонения окружения** — порт Redis `6380` и порт API `8000` на
   dev-машине заняты чужими контейнерами (KI-001, KI-002); фактически
   используются `6381` и `8010`. Это не меняет продукт, но меняет
   команды проверки на этой машине.
3. **`localhost` запрещён в конфигах** — только `127.0.0.1` (`RULES.md`
   §11.1).
4. **Ingestion готов (T-007)** — `app/ingestion/`: `parse_pgn`,
   `parse_fen`, `find_position_repeats`; ECO = заголовок PGN + курируемая
   таблица префиксов (полная база — KI-011); детект тихого обрыва PGN —
   KI-012.
5. **Engine готов (T-008)** — `app/engine/`: `EngineService.analyze`
   (MultiPV 1/3/5, глубины 12/18/28, бюджеты 0.2/1/5 с),
   `classify_move`, `analyze_game_moves`; собственный async UCI-клиент
   (не библиотека `stockfish`). Бинарник на этой машине —
   `D:\Tools\stockfish\stockfish.exe` (`STOCKFISH_PATH`, KI-006).
   Ограничение: TCP-транспорт — KI-013.
6. **API готов (T-009)** — `POST /v1/analyze` (`app/api/v1/analyze.py`):
   PGN + уровень → JSON + запись в `games`/`moves`. Пул
   `EnginePool(4)` (`ENGINE_POOL_SIZE`, до 8) закрыл KI-014: 53 полухода
   на «клубе» — **14.6 с** (лимит 30 с). Доменные ошибки → 400/422/500/504
   (`{"detail", "code"}`); rate limit 10/мин на IP (Redis).
   Ограничения: SLA не гарантируется для 160+ полуходов (KI-017),
   `moves.multipv` не заполняется (KI-018), `analysis_id` — bigint
   строкой (KI-016), rate limit fail-open (KI-015).
7. **Мотивы готовы (T-010)** — `app/motifs/`: `detect_motifs` (проходные
   пешки, слабые поля, открытые линии/диагонали, безопасность короля,
   вилки/связки, мат/выигрыш материала); мотивы пишутся в таблицу `motifs`;
   PV-линии — в `moves.multipv` (KI-018 закрыт). Ограничение: recall не
   измерен (KI-019).
8. **Policy готова (T-011)** — `app/engine/policy.py`:
   `choose_recommended_move(multipv, level, fen=...)`; в API пока не
   выводится (T-012). Ограничение: новичок без SEE (KI-020).
9. **API расширен (T-012)** — `/v1/analyze` отдаёт `moves` с мотивами и
   `recommended_move` (Policy под уровень). KI-020 закрыт: `mate > 0`
   разрешён новичку всегда.
10. **LLM готов (T-013)** — `app/llm/`: `beginner`/`club` → LM Studio
    (`http://127.0.0.1:8034/v1`, `qwen/qwen3-4b-2507`, ключ-заглушка
    `lm-studio`), `gm` → DeepSeek (`deepseek-chat`). Живой тест пройден:
    ≈1.7 с и ≈1.6 с, ответы «Привет, шахматы!». Стоимость не считается
    (KI-021), первый запрос к LM Studio ≈12 с (KI-022).
11. **Промпты и пакет фактов (T-014)** — `app/prompts/{beginner,club,gm}.txt`
    (SAN без Markdown, только факты из пакета), `build_fact_package` в
    `app/llm/prompts.py` (до 10 ключевых моментов с оценкой, классом,
    рекомендацией, PV и мотивами), прогрев LM Studio в lifespan
    (`app/llm/warmup.py`, KI-022 закрыт).
12. **Валидатор (T-015)** — `app/engine/validator.py`: SAN-регэксп,
    проигрывание на доске, альтернативы по позициям партии. Ограничение:
    проверяется только легальность, не семантика оценок (KI-023).
13. **Комментарий готов (T-016)** — `POST /v1/commentary`: `analysis_id` →
    партия и анализ из БД → пакет фактов → LLM → валидатор (до 2 retry) →
    запись в `commentaries`. Нелегальные ходы → 502, запись не создаётся.
14. **RAG готов (T-017)** — `POST /v1/ingest` (multipart PGN, до 5 МБ),
    хеш-эмбеддинги 1024 (заглушка, KI-025), `find_similar_positions` по FEN,
    RAG-контекст для `gm` в `/v1/commentary`.
15. **Следующая итерация** — T-018 (кэш retrieval, top-k по уровням) или
    Фаза 5 (T-019 React). До публичного деплоя закрыть KI-026 (`/v1/ingest`
    без auth) и учесть KI-024 (генерация ~54 с → стриминг/фон).
