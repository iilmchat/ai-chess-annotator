## 1. Модель

`app/motifs/models.py`:

```python
MotifType = Literal["passed_pawn", "weak_square", "open_file",
                    "open_diagonal", "king_safety", "fork", "pin",
                    "mate_threat", "winning_capture"]

class Motif(BaseModel):      # frozen, extra="forbid"
    type: MotifType
    description: str          # 1…200 символов, по-русски
    importance: int = Field(ge=1, le=5)
```

`Literal` вместо `str` — потому что по типу мотива дальше строятся промпты
(T-014) и фильтры; опечатка должна падать на тесте, а не в проде.
`importance` 1…5 — для сортировки и для «веса» в тексте.

## 2. Детектор: что и как ищется

| Мотив | Правило | Важность |
| :--- | :--- | :--- |
| `passed_pawn` | нет пешек соперника на своём и соседних файлах впереди; пешка не на 1–2-й горизонтали | 5 (6–7-я), 4 (5-я), 3 (3–4-я) |
| `weak_square` | пустое поле 3–6-й горизонтали рядом с королём (≤ 2 клеток), которое не защитить пешкой; не центральный файл; у стороны ≥ 4 пешек; одно поле на короля | 4 |
| `open_file` | файл без пешек обеих сторон, на нём ладья/ферзь | 4 (рядом с королём) / 3 |
| `open_diagonal` | большая диагональ (a1–h8 / h1–a8) без пешек, на ней слон/ферзь | 3 |
| `king_safety` | король в центре при ферзях; или рокированный король без пешки f | 4 / 3 |
| `fork` | фигура стороны, которая ходит, атакует ≥ 2 цели (король или ≥ 300 cp) | 4 |
| `pin` | `board.is_pinned(enemy, square)` для фигур соперника | 3 |
| `mate_threat` | `multipv[0].mate > 0` | 5 |
| `winning_capture` | лучший ход — взятие; выигрыш ≥ 200 cp и поле не защищено | 3 |

Выход: дедупликация по `(type, description)`, сортировка по важности,
не больше `MAX_MOTIFS = 6` — иначе текст и БД тонут в шуме.

## 3. Отладка шума (две итерации эвристик)

Первая версия на стартовой позиции выдавала **4 «слабых поля»** (b1, c1,
f1, g1) — в позициях без пешек «дырой» становится почти любое поле.
После фильтров:

* у стороны должно быть ≥ 4 пешек (в пешечных окончаниях «дыры» не имеют
  смысла);
* поле — 3–6-я горизонталь стороны (1–2-я — тыл);
* не центральные файлы (там борьба за центр, а не дыра);
* одно поле на короля (ближайшее).

Аналогично `passed_pawn`: в позиции без пешек соперника **каждая** пешка
формально проходная; теперь пешка на своей 1–2-й горизонтали не считается
мотивом (`advanced >= 2`).

Проверка на 54 позициях партии Гукеш — Каймер: `weak_square` 45,
`king_safety` 35, `passed_pawn` 10, `pin` 10, `open_file` 7, `fork` 2,
`open_diagonal` 2 — шума, забивающего текст, нет.

## 4. Разрыв цикла импорта

`app.engine.models.MoveAnalysis` содержит `motifs: list[Motif]` →
`engine.models` импортирует `app.motifs.models`. Если бы `app/motifs/__init__`
тянул детектор, а детектор — `EngineLine`, получался бы цикл:

```
engine.models → motifs.__init__ → motifs.detector → engine.models (partial)
```

Решение: `motifs.detector` импортирует `EngineLine` только под
`TYPE_CHECKING` (аннотации отложены `from __future__ import annotations`).
Рантайму класс не нужен — детектор читает атрибуты переданных линий.
