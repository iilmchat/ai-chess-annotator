## 4. Smoke

Ручной сценарий (эквивалент автоматизирован в `analyze.spec.ts` +
`pgn-export.spec.ts`, mocked-режим; выполнялся через `E2E_PREVIEW=1`,
preview раздаёт `dist`):

1. Открыть `/`, вставить PGN, уровень «Клубный игрок», «Разобрать».
2. Доска появляется вместе со шкалой оценки слева: `role="meter"`,
   белая часть сверху; на стартовой позиции доля белых `0.50`.
3. Под доской — кнопки `|<< ◀ ▶ ▶|`; после анализа выбран последний
   полуход, поэтому «вперёд»/«в конец» `disabled`; «в начало» →
   `selected-ply` = 0, шкала `0.50`, «в начало»/«назад» `disabled`.
4. «Вперёд»/«назад» двигают выбор на один полуход; «в конец» возвращает
   на последний и снова выключает «вперёд»/«в конец».
5. Клик по графику оценки в точке ~70% ширины переключает доску на
   ближайший полуход (маркер и шкала обновляются).
6. Чекбокс «Показывать оценки» скрывает числовые оценки в списке ходов
   (классификация `?!`/`?`/`??` и цвет остаются), повторный клик
   возвращает числа.
7. Карточка хода с мотивами: вместо `weak_square`/`pin` — «Слабое поле»,
   «Связка»; переключение языка на EN → «Weak square», «Pin».
8. Наведение на бейдж лимита: `title` «Израсходовано токенов LLM:
   9 300 из 50 000 (дневной лимит)» (в E2E — «0 из 50 000» для мока).
9. «Скачать PGN» → скачивается `chessannotator-<id>.pgn`; файл
   открывается в PGN-редакторе: заголовки, ходы с комментариями
   `{+0.35, good}`, результат-токен.
10. Перезагрузка страницы: анализ сохраняется (sessionStorage) — регрессий
    персиста нет.

Проверено также, что после code-split переход `/` → `/analysis/:id`
работает без мигания ошибок (`Suspense` + `Skeleton`).

| Заголовки скачанного PGN минимальны | `GET /v1/games/{id}` не отдаёт исходный PGN, а `AnalysisPage` его не хранит, поэтому кнопка собирает партию по SAN: `Event "ChessAnnotator"`, `White/Black "?"`, `Result "*"` (ходы и аннотации — полные). ## 7. Обоснование

- **Почему recharts и почему отдельный чанк.** График — стандартный
  React-инструмент (recharts — по требованию задачи). Библиотека тяжёлая,
  поэтому по RULES §3.2 сделан route-level split: `HomePage` и
  `AnalysisPage` ленивые (`React.lazy` + `Suspense`), recharts уезжает в
  асинхронный чанк. Проверено: ленивая только `AnalysisPage` не помогала —
  `HomePage` тоже рендерит workspace, поэтому ленивые обе страницы.
- **Почему логика оценки вынесена в `lib/eval.ts`.** Чистые функции
  (clamp/share/mate) тестируются в node-окружении без jsdom и переиспользуются
  шкалой и графиком — один источник правды для «насколько белые лучше».
- **Почему навигация без нового глобального стейта.** `selectedPly` уже
  живёт в `analysisStore` (персистится), `NavigationControls` — чистый
  компонент на пропсах; так его поведение (границы, clamp) проверяется
  E2E-сценарием и не дублирует состояние.
- **Почему toggle оценок — локальный `useState`.** Это UI-предпочтение
  просмотра, а не данные анализа; персистить его не нужно, а локальное
  состояние исключает лишние перерисовки всего workspace.
- **Почему PGN собирается на клиенте.** Требование задачи: `chess.js`
  уже в бандле, аннотации берутся из `analysis.moves`; комментарии
  санитайзятся (`{}` → `()`, переводы строк → пробел), чтобы текст LLM
  не ломал PGN-структуру, а файл остаётся валидным и re-parsable.
- **Почему мотивы переводятся на UI-слое.** Типы мотивов — часть API
  (`Literal`, стабильный контракт), поэтому перевод — только отображение
  (`t("motifs.<type>")` + fallback на сырой тег). Новый тип мотива в
  бэкенде не сломает интерфейс, а известные 9 типов показываются
  человеческими словами в RU и EN.
- **Почему такой сплит работы.** Два потока с непересекающимися
  write-scope: (A) визуальные компоненты + CSS + E2E analyze,
  (B) локализация/тултип/PGN + интеграция workspace. Контракты
  (props компонентов) и все i18n-ключи зафиксированы Lead до старта —
  поэтому потоки не конфликтовали, а итоговая сборка/типы/тесты сошлись
  с первого прогона (после единственной правки — code-split `App.tsx`,
  авторизованной Lead по факту регрессии размера чанка).
