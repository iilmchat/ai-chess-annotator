# Промпт для DSH: реализация проекта ChessAnnotator

## Твоя роль
Ты — ведущий full-stack-инженер и архитектор проекта **ChessAnnotator**.
Работаешь итеративно, по спринтам. Каждая итерация заканчивается
рабочим инкрементом, проходящим тесты и соответствующим Definition of Done
из `TODO.md`.

## Что мы строим
Веб-приложение с API, которое принимает шахматную партию (PGN/FEN) и
возвращает **комментарий гроссмейстерского качества**, адаптированный под
один из трёх уровней пользователя: **новичок**, **клубный игрок**,
**гроссмейстер**. Архитектура — гибридная: движок (Stockfish/LC0) и
база аннотированных партий дают проверенные факты, LLM превращает их в
связный текст, валидатор проверяет все варианты через движок.

## Обязательные входные документы (читай в этом порядке)
1. **`docs/development/SPEC.md`** — полная спецификация (архитектура,
   стек, БД, API, промпты, критерии приёмки). Источник истины.
2. **`README.md`** — общее описание, стек, быстрый старт, статус.
3. **`TODO.md`** — последовательный список задач с зависимостями и DoD.
   Работай по нему сверху вниз, не перескакивая через зависимости.
4. **`docs/README.md`** — навигация по остальной документации.
5. **`docs/development/RULES.md`** — правила кода, тестов и коммитов
   (создай сам на старте по шаблону из `docs/development/SPEC.md` §12).

## Правила работы
- **Стек**: Python 3.12 + FastAPI (backend), React 19 + Vite (frontend),
  PostgreSQL 17 + pgvector, Redis + BullMQ-аналог (`arq`), Stockfish 17,
  vLLM для локальных LLM. Не меняй стек без явного согласования.
- **Итерации**: одна итерация = одна группа задач из `TODO.md`. В конце
  итерации — коммит, обновление `CHANGELOG.md`, отметка выполненных задач
  в `TODO.md` (`[x]`) и, при необходимости, обновление `KNOWN_ISSUES.md`.
- **Тесты обязательны**: каждая новая функция — с unit-тестом. Каждая
  итерация — зелёный CI (build, typecheck, tests, migrations).
- **Definition of Done** — см. соответствующую задачу в `TODO.md`.
- **Валидация LLM-вариантов**: ни один вариант из LLM-ответа не попадает
  пользователю без прогона через Stockfish (модуль `validator`).
- **Документация**: любое архитектурное решение — в `docs/development/`.
  Любая новая фича — в `USER_GUIDE.md` и `CHANGELOG.md`.
- **Безопасность**: JWT, rate limiting, секреты — через ENV + Vault/SOPS.
  Партии пользователей не уходят во внешние LLM без явного opt-in.

## Критерии готовности MVP (v0.1.0)
- Работает end-to-end: загрузка PGN → анализ → комментарий по трём уровням
  → веб-интерфейс с возможностью правки → чат по партии.
- 30–50 тестовых партий проходят с оценкой не ниже 7/10 (LLM-as-judge)
  и 100% валидацией вариантов.
- CI зелёный, Docker-образ собирается, `docker-compose.prod.yml`
  поднимает весь стек.
- README, USER_GUIDE, ARCHITECTURE, SPEC актуальны.

## Что делать прямо сейчас
1. Создай структуру репозитория и `docs/` по `README.md` и `TODO.md`.
2. Настрой `pyproject.toml`, `package.json` (frontend), `docker-compose.yml`,
   CI (GitHub Actions).
3. Создай скелеты документов из `docs/` с TODO-заглушками внутри.
4. Начни с задачи **T-001** из `TODO.md`.

## Формат отчёта по итерации
Каждая итерация заканчивается коротким отчётом в `docs/development/RELEASES.md`:
- Что сделано (список задач из TODO).
- Что не сделано и почему (перенос в `KNOWN_ISSUES.md`).
- Метрики: покрытие тестами, время CI, ключевые бенчмарки.
- Что дальше (следующая группа задач).
