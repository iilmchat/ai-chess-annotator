# STEP-09 — Фикстура PGN (T-007, подготовка)

**Дата:** 2026-10-28
**Итерация:** 1 — Bootstrap (T-001…T-006)
**Статус:** ✅ выполнен (фикстура была в bootstrap, но **не читалась** — исправлено)

---

## 1. Что обнаружено

`tests/fixtures/example.pgn` уже лежал в bootstrap-коммите и содержал
**ту же партию**, что в постановке (Гукеш — Каймер, Прага 2024, ходы
`1.d4 Nf6 … 27.Bg6+ 1-0`), но с полным набором заголовков из TWIC — это
лучше, чем обезличенная «Test White / Test Black», поэтому текст партии
сохранён.

**Проблема:** первая строка файла была не-PGN-текстом:

```
Партия 2. Д.Гукеш - В.Каймер, 2024
```

Из-за неё `chess.pgn.read_game()` возвращал **пустую партию**:

```
headers: {'Event': '?', 'Site': '?', ..., 'Result': '*'}
plies: 0 | moves match: False
```

То есть фикстура для T-007 была бы бесполезна, а тест «10 PGN разбираются
корректно» — ложно-зелёным.

## 2. Что сделано

1. Удалена ведущая строка-описание; файл приведён к валидному PGN
   (заголовки + пустая строка + movetext). Описание партии перенесено в
   новый `tests/fixtures/README.md`, чтобы не терять provenance.
2. Добавлен `tests/fixtures/README.md`: источник (TWIC 1531), инварианты
   для тестов (53 полухода, `1-0`, ECO `E21`, последний ход `Bg6+`) и
   объяснение, почему строка убрана.
3. Фикстура проверена `python-chess` — см. § 3.

## 5. Почему не заменил на «Test White / Test Black»

- Ходы, результат и структура — те же; отличие только в именах и
  метаданных.
- Реальный PGN с заголовками `ECO`, `WhiteElo`, `EventDate`, `PlyCount`
  полезнее для T-007: ECO-классификация и разметка фаз проверяются на
  настоящих данных.
- Обезличенная фикстура не проверяет парсинг заголовков (а это часть
  ingestion).
