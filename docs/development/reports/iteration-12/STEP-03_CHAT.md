# STEP-03 — `POST /v1/chat` (T-022)

**Дата:** 2026-10-28
**Итерация:** 12
**Задача:** T-022 (серверная часть)
**Статус:** ✅

## Что сделано

1. `app/chat/service.py`:
   - `answer_question(session, analysis_id, level, message)` — загружает
     `games`/`moves`/`motifs` через `load_game` + `load_analyses` (T-016),
     собирает пакет фактов `build_fact_package` (метаданные, все ходы,
     ключевые моменты, оценки, лучший ход, рекомендации, PV, мотивы);
   - системный промпт `CHAT_SYSTEM_PROMPT`: «Ты — шахматный ассистент.
     Отвечай на вопрос пользователя, опираясь только на факты из
     предоставленного анализа партии»;
   - `build_chat_prompt` добавляет вопрос и требование отвечать по фактам;
   - LLM выбирается `get_llm_client(level)` (club → LM Studio, gm → DeepSeek);
   - ответ проходит `extract_moves_from_text` + `validate_moves` (mainline и
     позиции PV); при нелегальных ходах — retry с перечислением нарушений
     (до `chat_max_retries + 1` попыток), затем `LLMValidationError` (502).
2. `app/api/v1/chat.py` — `POST /v1/chat`:
   - запрос `{"analysis_id", "level", "message"}`; `message` 1..2000,
     пробельный отклоняется;
   - ответ `{"reply": "...", "tokens_used": 1950}`;
   - 404 — нет партии/анализа, 422 — тело, 502 — нелегальные ходы после
     retry, 503/504 — ошибки LLM (общий обработчик).
3. `POST /v1/chat` добавлен в rate limiting (`RateLimitMiddleware`).
4. Тесты `tests/integration/test_api_chat.py` (9):
   - «Кто играл белыми?» → ответ содержит имена, в промпте есть
     `Белые: Svidler` / `Чёрные: Shirov`;
   - нелегальный `Qxf7` → retry, во втором промпте есть `Qxf7` и требование
     использовать только ходы из пакета; успешный ответ `attempts=2`;
   - все попытки нелегальны → `LLMValidationError` (502);
   - неизвестный `analysis_id` → 404;
   - валидация тела: пустой message / уровень `master` / `analysis_id=0` → 422;
   - живой тест: `/v1/analyze` + `/v1/chat` через LM Studio.

## Проблемы и отклонения

- **KI-028 (открыт).** Ответ синхронный, без SSE и истории диалога;
  локальная модель отвечает 12–31 с. Контракт итерации — JSON, но UI-чат
  потребует стриминга.
- **KI-023 (открыт).** Валидатор проверяет только легальность SAN, не
  атрибуцию оценок. Живой пример: модель назвала `e5` лучшим ходом и
  «потерю 112 cp» в одном предложении — ходы легальны, но формулировка
  неточна. Это ограничение известно.
- **KI-027 (открыт).** React-чат-клиента и SSE в checkout нет; T-022
  закрыта в серверном объёме.

## Обоснование решений

- Переиспользованы `load_game`/`load_analyses`/`build_fact_package` из
  T-016: контекст чата и комментария обязан совпадать, иначе LLM получает
  разные факты об одной партии.
- Отдельный `CHAT_SYSTEM_PROMPT`, а не промпты уровней: те задают формат
  комментария (200–350 слов, структура), а чату нужен ответ на вопрос.
- Валидация — по mainline **и** позициям PV: вопрос может цитировать
  вариант движка, который не входит в партию.
- RAG-контекст в чат не подключён: постановка требует метаданные, ключевые
  ходы, мотивы и оценки; RAG для gm можно добавить отдельной задачей.
