## 2. Разведка поведения `python-chess` (до написания кода)

Прогон на граничных входах — чтобы обработка ошибок опиралась на факты,
а не на ожидания:

| Вход | Результат |
| :--- | :--- |
| `""` | `read_game` → `None` |
| `"это не pgn вообще"` | `game` **не** `None`, но 0 ходов, `errors=[]` |
| `"1. e4 e5 2. Nf3"` | 3 хода, все заголовки `?`, `errors=[]` |
| `"1. e5 e4 *"` | `errors=[IllegalMoveError(...)]`, 0 ходов |
| `"1. e4 e5 2. Zz9"` | **2 хода, `errors=[]`** — тихий обрыв (KI-012) |
| FEN `"not-a-fen"` | `ValueError: expected 8 rows…` |
| FEN без королей | `Board` создаётся, `is_valid() == False` |
| FEN `"… w"` (неполный, 2 поля) | создаётся, `is_valid() == True` |

Выводы, заложенные в код:

1. Проверять мало `game is None` — «мусор» даёт валидный `game` без ходов,
   поэтому обязательна проверка «есть хотя бы один ход».
2. `game.errors` ловит нелегальные SAN, но **не** ловит нераспознанные
   токены → отдельный `xfail`-тест и KI-012.
3. FEN валидируется в два шага: конструктор (`ValueError`) и
   `board.is_valid()` (невозможные позиции).
4. `Result` подставляется `python-chess` из терминатора movetext-а даже без
   заголовков (`"1. e4 e5 1/2-1/2"` → `1/2-1/2`).

## 3. Контракт ошибок: `app/errors.py`

RULES §3.1 требует собственных исключений в `app/errors.py` — файла ещё не
было (итерация 1 не создавала доменных ошибок).

```python
class AppError(Exception):
    code: str = "app_error"
    http_status: int = 400

class InvalidPgnError(AppError):
    code = "invalid_pgn"

class InvalidFenError(AppError):
    code = "invalid_fen"
```

Почему так:

- **`code` + `http_status` сразу.** T-009 будет маппить их в ответы API;
  обработчик напишется один раз и не будет знать про `python-chess`.
- **Наследование от `AppError`.** Позволит ловить «все доменные ошибки»
  одним `except AppError` (middleware/логирование).
- **Никаких `ValueError` наружу.** Модуль ingestion переводит
  `ValueError` из `python-chess` в `InvalidFenError` с `from exc`, чтобы
  сохранить исходный traceback.
