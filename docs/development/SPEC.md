## 1. Цель и видение

Создать **веб-приложение с API**, которое принимает шахматную партию (PGN/FEN)
и возвращает **комментарий гроссмейстерского качества**, адаптированный под
один из трёх уровней пользователя: **новичок**, **клубный игрок**,
**гроссмейстер**.

Система должна:

- Опираться на **проверенные факты** (движок Stockfish + базы партий), а не
  на «фантазии» LLM.
- Генерировать **связный текст** через LLM, стилизованный под
  гроссмейстерские аннотации (в духе Рафаэля Лейтао).
- Работать как **stateless API** + отдельный **чат-клиент** для уточняющих
  вопросов.
- Иметь **гибридную модель развёртывания**: локальные модели для новичков,
  облако/локально для клуба, облако + RAG для гроссмейстеров.

### 2.1. Ingestion

- Вход: PGN, FEN, ручной ввод.
- `python-chess`: проверка легальности, ECO-классификация, детект
  транспозиций.
- Разметка фаз: дебют / миттельшпиль / эндшпиль (по числу фигур + номеру
  хода).

### 2.2. Engine Service

- **Stockfish** (основной) + **Leela Chess Zero** (для гроссмейстерского
  уровня).
- Параметры по уровням:
  - новичок: `depth=12`, MultiPV=1, ~0.2 сек/ход
  - клуб: `depth=18`, MultiPV=3, ~1 сек/ход
  - гроссмейстер: `depth=28+` или `movetime=5000ms`, MultiPV=5
- Для каждого хода: оценка (cp/mate), лучший ход, delta-оценка,
  единственность (best move = only move?), classification
  (blunder/mistake/inaccuracy/good/best/brilliant).

### 2.3. RAG Service

- **Источники**:
  - ChessBase Mega Database 2026 (11.7M партий, 114k+ с аннотациями) — при
    наличии лицензии.
  - Открытые аннотированные партии (Lichess Studies, открытые книги).
  - Своя растущая база через модуль 7.
- **Хранилище**: PostgreSQL + `pgvector`. Эмбеддинги позиций — через
  LM Studio `text-embedding-nomic-embed-text-v1.5` (768, L2); задел на
  `bge-m3` / `text-embedding-3-large`.
- **Retrieval**: top-k похожих позиций + их аннотации → передаются в LLM
  как «контекст гроссмейстера».

### 2.4. Motif Detector

Комбинируем эвристики `python-chess` (материал, пешечная структура,
безопасность короля) + фичи движка (мобильность, контроль полей). На
выходе — структурированный JSON мотивов, привязанных к ходам.

### 2.5. Policy Layer (ключевая инновация)

**Детерминированная функция выбора «рекомендуемого хода под уровень»**, а
не просто топ-1 движка:

- **Новичок**: выбирается ход из top-3 движка, который **не является
  зевком** (delta ≤ 250 cp) и **соответствует базовым принципам**
  (развитие, центр, безопасность короля). Если top-1 нарушает принципы —
  берём следующий.
- **Клубный**: top-3, объясняем альтернативы, ищем тактические мотивы.
- **Гроссмейстер**: top-1 или top-line с длинными вариантами, объяснение
  стратегических нюансов.

### 2.6. LLM Generation + Validator

- Промпт получает **структурированный пакет**: ход, оценка до/после,
  лучший вариант, мотивы, retrieved-аннотации, целевой уровень.
- LLM (модель по уровню, см. §3) генерирует текст.
- **Валидатор**: каждый вариант из ответа прогоняется через Stockfish;
  нелегальные/ошибочные → автоматический retry с уточнением.

### 2.7. Human-in-the-loop

- Веб-редактор: правки комментария, изменение глубины, добавление
  «изюминки».
- Правки → в **датасет для дообучения/настройки промптов** (LoRA для
  локальных моделей, few-shot для облачных).

## 3. Три уровня ассистента

| Параметр | Новичок | Клубный игрок | Гроссмейстер |
|---|---|---|---|
| **Движок** | Stockfish depth=12, 0.2с/ход | Stockfish depth=18, 1с/ход | SF depth=28+ / LC0, 5с/ход |
| **LLM** | Локальная лёгкая (Qwen3-1.7B / Gemma-3-4B, файнтюн) | Локальная средняя (Qwen3-8B / Llama-3.1-8B) или облачная mini | Облачная мощная (GPT-5 / Claude Sonnet / DeepSeek-V3.2) + RAG |
| **RAG** | Не нужен (базовые принципы) | Средний (похожие партии, статистика) | Полный (аннотации, история варианта, новинки) |
| **Стиль** | Простой язык, «почему это работает», акцент на типичные ошибки | Баланс тактики и стратегии, объяснение альтернатив | Профессиональный, тонкие нюансы, отсылки к истории |
| **Policy** | «Не зевок + принцип» | Top-3 + мотивы | Top-line + стратегия |
| **Стоимость/ход** | ~$0.0001 | ~$0.001 | ~$0.01–0.05 |

## 4. Схема базы данных (PostgreSQL)

```sql
-- Пользователи и уровни
users(id, email, level ENUM('beginner','club','gm'),
      role ENUM('user','admin','auditor') DEFAULT 'user',
      is_active BOOL DEFAULT true, password_hash TEXT, last_login_at,
      created_at)

-- Партии
games(id, user_id, pgn TEXT, eco_code, phase_breakdown JSONB,
      analysis_level ENUM('beginner','club','gm') DEFAULT 'club',
      analysis_time_ms INT, created_at)

-- Анализ по ходам
moves(id, game_id, ply, san, fen, eval_cp, eval_mate,
      best_move_san, delta_cp, classification,
      engine_depth, multipv JSONB)

-- Мотивы (привязка к ходам)
motifs(id, move_id, type, description, importance SMALLINT)

-- Аннотированные партии (для RAG)
annotated_games(id, source, pgn, white, black, event, year,
                annotation_text TEXT, embedding vector(768))

-- Retrieval-кеш
retrieval_cache(id, fen_hash, top_k_ids INT[], created_at)

-- Комментарии (сгенерированные)
commentaries(id, game_id, user_id, level, text TEXT, model,
             tokens_in, tokens_out, cost_usd, validated BOOL,
             human_edited BOOL, created_at)

-- Правки (для датасета дообучения)
edits(id, commentary_id, original_text, edited_text, user_id,
      editor_id, created_at)

-- Промпты уровней (T-029, итерация 17)
prompts(id, level VARCHAR(32) UNIQUE, content TEXT,
        version INT, updated_at TIMESTAMPTZ)

-- Аудит действий (T-035, итерация 18): append-only + hash-chain
audit_logs(id, timestamp, actor, action, target_id,
           details JSONB, prev_hash, current_hash)

-- Semantic cache (T-032, итерация 19): exact + vector поиск
semantic_cache(id, fen_hash, fen_embedding vector(768), level,
               prompt_hash, response_text TEXT, created_at)

-- Кэш результатов движка (T-108, итерация 30)
engine_cache(id, fen_hash, engine_version, depth, multipv,
             lines JSONB, created_at)

-- LLM-as-judge (T-039, итерация 22)
llm_evaluations(id, model, level, accuracy_score, usefulness_score,
                style_score, created_at)
```

### 2.3. История и лимиты

- `GET /v1/games?limit=20` — последние партии: `id`, `white`, `black`,
  `event`, `level`, `created_at`.
- `GET /v1/users/me/usage` — `tier`, `used_tokens`, `limit_tokens`,
  `remaining_tokens`, `reset_at`, `enabled`; субъект — IP + `PRO_IPS`.
- `POST /v1/chat` и `/v1/chat/stream` принимают `history` (до 20 реплик
  `user`/`assistant`); user-реплики повторно проверяются guardrails.

**Индексы:** `moves(game_id, ply)`,
`annotated_games USING ivfflat (embedding vector_cosine_ops)`,
`retrieval_cache(fen_hash)`, `engine_cache(fen_hash, engine_version, depth,
multipv)` — уникальный ключ кэша движка + `engine_cache(created_at)` для
чистки по TTL.

## 5. API (FastAPI, OpenAPI 3.1)

| Метод | Endpoint | Описание |
|---|---|---|
| `POST` | `/v1/analyze` | Принимает PGN/FEN, `level`, возвращает структурированный анализ (moves, evals, motifs). **Без LLM** — быстро. |
| `POST` | `/v1/commentary` | Принимает `analysis_id` или PGN, `level`, `style`, возвращает сгенерированный комментарий. |
| `POST` | `/v1/chat` | Чат по партии: `{analysis_id, message}` → ответ LLM с проверкой вариантов. |
| `GET` | `/v1/games/{id}` | Метаданные партии и сохранённые комментарии. |
| `PATCH` | `/v1/commentaries/{id}` | Правка комментария (human-in-the-loop). |
| `GET` | `/v1/commentaries/{id}/export/pdf` | PDF-экспорт комментария: шапка партии, ходы, текст; `Content-Disposition: attachment` (T-107). |
| `POST` | `/v1/ingest` | Загрузка аннотированных партий в RAG (админ). |
| `GET` | `/v1/health` | Healthcheck движка, БД, LLM. |

**Аутентификация:** JWT (`POST /auth/register|login|refresh|logout`,
`GET /auth/me`; access 15 мин + refresh 7 дней; заголовок
`Authorization: Bearer <access>`). Refresh-токен передаётся в
HttpOnly-cookie (`SameSite=Lax`, `Path=/auth`, `Secure` в prod), при logout
его `jti` уходит в Redis-denylist, а ротация инвалидирует прежний refresh;
не-браузерные клиенты могут передать refresh в теле. Пароли —
**Argon2id** (`argon2-cffi`), legacy bcrypt-хеши перехешируются при входе.
Роли `user/admin/auditor` (enum `admin_role`); `/admin` принимает access JWT
admin/auditor. Чтение/запись партий, ходов,
комментариев и чата — с изоляцией по владельцу: обычный пользователь
видит только свои `games`, администратор — все; чужой id неотличим от
несуществующего (404). **Rate limiting:** через Redis (в т.ч.
`/auth/login|register`). **FinOps:** дневной бюджет токенов считается по
`user:{id}` из JWT, анонимно — по IP.

## 6. Системные промпты (черновики)

### 6.1. Новичок

```text
Ты — терпеливый тренер для начинающих. Объясняй ходы простым языком,
без сложной терминологии. Фокусируйся на: (1) безопасности короля,
(2) развитии фигур, (3) контроле центра, (4) типичных ошибках новичков.

Для каждого ключевого хода:
- Что произошло?
- Почему это хорошо/плохо?
- Какой принцип здесь работает?
- Что было бы лучше и почему?

ЗАПРЕЩЕНО выдумывать варианты. Используй только факты из пакета.
```

### 6.2. Клубный игрок

```text
Ты — гроссмейстер-комментатор для игроков уровня 1800–2200.
Балансируй тактику и стратегию. Объясняй альтернативы, переломные
моменты, типовые планы. Ссылайся на статистику из базы, если она есть.

Для каждого ключевого хода: оценка, лучший вариант, мотив,
альтернатива, типовой план в этой структуре.

Все варианты — только из пакета. Формат: как у Рафаэля Лейтао.
```

### 6.3. Гроссмейстер

```text
Ты — гроссмейстер, пишущий для гроссмейстеров. Используй
профессиональную терминологию, тонкие стратегические нюансы,
отсылки к истории варианта (если есть в retrieved-контексте).

Формат: ход → оценка → вариант → стратегическая идея →
исторический контекст / новинка.

Стиль: сдержанный, ироничный, как у Лейтао/Каспарова.
Все варианты валидируются движком перед отправкой.
```

## 9. Критерии приёмки

1. **Фактическая точность**: 100% вариантов в комментарии легальны и
   валидированы Stockfish (автотест).
2. **Уровневая адаптация**: слепой тест 10 шахматистов — 80%+ правильно
   определяют целевой уровень комментария.
3. **Покрытие ключевых моментов**: система находит все ходы с
   delta ≥ 200 cp (blunder/mistake) — recall ≥ 95% на тестовом наборе.
4. **Стиль**: LLM-as-judge сравнение с эталонными комментариями Лейтао —
   не ниже 7/10.
5. **Латентность**: `/v1/analyze` ≤ 30 сек на партию из 40 ходов
   (уровень «клуб»).
6. **Стоимость**: средний комментарий «новичок» ≤ $0.005,
   «гроссмейстер» ≤ $0.10.

## 10. Non-functional

- **Приватность**: партии пользователей не уходят в облако при уровне
  «новичок» (локальная LLM). Для «гроссмейстера» — опция «только
  локально».
- **GDPR**: право на удаление, экспорт данных.
- **Масштабирование**: горизонтальное, stateless API, движки в пуле.
- **Отказоустойчивость**: fallback локальная LLM → облачная; кэш
  retrieval.
- **Admin Control Plane**: защищённая панель `/admin` (`starlette-admin`)
  с ролями `user` / `admin` / `auditor`; управление `annotated_games` и
  `commentaries`, версионирование промптов, выгрузка `edits`, аудит.
  Админ-операции недоступны через публичный API без роли.
- **Observability (LLMOps)**: сквозной `trace_id` (W3C Trace Context) от
  HTTP-запроса до вызова LLM, валидатора и RAG; OTel-спаны с экспортом
  OTLP; durable-запись `llm_calls` (`model`, `tokens_in/out`,
  `cost_usd`, `latency_ms`, `cache_hit`, `status`); дашборды p50/p95,
  error rate и стоимости; PII в трейсы не попадает.
- **FinOps**: контроль стоимости и токенов на пользователя/IP/глобально
  (день/месяц), бюджеты в `system_settings`, ответ `429` при исчерпании,
  учёт `cost_usd` по прайсу модели, алерты 80/100% бюджета и отчёт
  «стоимость на комментарий/уровень».

Детали схемы, админки, трейсинга и guardrails —
[DESIGN_ADMIN_AND_OPS.md](DESIGN_ADMIN_AND_OPS.md).
